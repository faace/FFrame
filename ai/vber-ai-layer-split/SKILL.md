# VberAI 图片分层

把一次分层任务分成“定位图片 → 进入图层拆分 → 理解 → 计划 → 程序化框选 → 排序 → 确认 → 提交 → 可选下载”。不要依赖逐个目测拖框。

## 前置门禁

任何读图、候选清单、框选计划或画框操作开始前，必须先确认页面已经进入目标图片的“图层拆分”步骤：

1. 在主编辑器中按精确名称定位并选中目标图片。
2. 点击该图片操作工具栏中的“图层拆分”。
3. 等待分层界面出现，并同时验证标题“图层拆分”、说明“框选元素”和“取消/下一步”操作区可见。

只选中图片、看到图片工具栏或在主编辑器中放大图片，都不算进入分层。若上述界面信号不存在，先进入分层并重新验证；禁止继续理解、计划、校准或框选。无法可靠进入时停止并报告。

## 输入

至少取得一种图片输入：

- 已在 VberAI 项目中的图片名称；或
- 需要粘贴到项目中的本地图片绝对路径。

同时取得：

- 用户大概需要的素材类型或用途。

可选取得：输出目录、是否拆文字、是否保留重复素材、是否下载、是否直接提交。

缺少可选项时采用默认值：

- 只保留运行时会独立显示、复用、点击、换皮或变更状态的素材。
- 相同视觉素材只拆一份。
- 按完整运行时组件划分；不要把按钮的底板、图标、装饰任意碎拆。
- 文字默认不拆，除非它是不可替换的美术字，或用户明确要求烘焙文字素材。
- 提交前必须让用户确认。
- 下载仅在用户提出时执行。

## 必须使用的能力

使用 `chrome:control-chrome` 操作用户已登录的 Chrome 和 VberAI 页面。先完整遵循该 Skill。

读取以下资源：

- 生成或检查计划时读取 [references/layer-plan-schema.md](references/layer-plan-schema.md)。
- 操作网页、排序、提交或下载时读取 [references/vber-browser-operations.md](references/vber-browser-operations.md)。

调用确定性工具：

- `node scripts/layer-plan.mjs validate <plan.json>`：校验并规范化计划。
- 在浏览器控制会话中导入 `scripts/vber-browser-tool.mjs`：换算坐标并程序化画框。
- `node scripts/layer-plan.mjs moves <current.json> <target.json>`：计算最少的相邻排序动作。

## 工作流

### 1. 把图片放入工作区、定位并进入分层

- **项目内图片**：按输入名称精确搜索并选择，不重复上传。
- **本地图片**：读取 PNG/JPEG 文件，通过标签页剪贴板写入图片；点击 VberAI 画布后执行 `Command/Ctrl + V`，等待新节点出现并按文件名重命名。不要寻找不存在的独立上传入口。

若有同名对象，先根据缩略图、尺寸和父级让用户确认，禁止凭索引猜测。本地图片粘贴失败时，先检查文件格式、剪贴板内容和画布焦点，只重试一次。

选择图片后必须执行“前置门禁”，进入并验证“图层拆分”界面。随后在分层画布中查看整图并记录源图固有宽高；后续矩形统一使用源图像素坐标，禁止记录屏幕坐标。

### 2. 理解素材需求

查看整图并生成候选清单。对每个候选判断：

1. 是否会被程序独立摆放、点击、隐藏、换图或复用？
2. 是否已经包含在更合理的完整组件内？
3. 是否与另一候选视觉等价，只需保留一次？
4. 是否只是背景纹理、阴影、装饰或可由 HTML/Vue/游戏引擎生成的文字？

优先保留完整功能组件、图标、按钮、进度条、头像框、货币底板等。背景可作为一个整体层。不要为了“拆得细”制造无用途的碎片。

### 3. 建立标准计划

按照 schema 生成 JSON。每个区域至少包含稳定 ID、语义名称、用途、源图像素矩形和层级优先级。

先在本地检查矩形：

```bash
node scripts/layer-plan.mjs validate /absolute/path/layer-plan.json
```

修复越界、重复 ID、无效尺寸和高重合警告。计划通过前不要操作网页。

### 4. 清理和程序化框选

若页面已有错误框选，先截图或读取现有数量并询问是否清空；用户已明确要求重做时可直接点击“清空全部”。

读取画布中源图的实际显示边界，调用 `drawRegionsWithCdp`。该工具按比例把源图坐标换算为视口坐标，并使用浏览器事件依次画框。不要用 AI 手工拖拽替代。

执行后核对：

- 页面区域数量与计划一致。
- 每个矩形的四边与目标边缘一致。
- 页面缩放或画布平移未在操作中变化。
- 控制点没有被当成新的起点。

若数量或坐标不符，停止并重新校准显示边界；不要在错误结果上连续补框。

### 5. 处理遮挡和排序

重叠区域由层级顺序决定像素归属。先识别缺块是否由相交区域造成，再修改顺序；不要先扩大矩形。

排序原则：

- 完整前景组件优先于其后的背景或大底板。
- 小而明确的独立图标通常高于覆盖范围更大的容器。
- 用户指定关系优先于自动规则。
- 无重叠区域的相对顺序无需调整。

读取页面当前顺序，用 `moves` 命令计算最少上移/下移动作，执行后逐项检查预览。层级按钮只用于排序，不应被误当作移动矩形位置。

### 6. 人工确认和提交

提交前向用户展示：

- 素材名称清单和数量。
- 画布框选截图。
- 存在重叠时的关键层级说明。
- 被去重或明确排除的候选。

等待用户确认后再提交。提交后定位新生成的 `_layer` 项目并核对层数、名称和预览完整性。

### 7. 可选下载

仅在用户需要时下载。优先读取编辑器已加载的节点图片数据或使用正式导出功能，保留 PNG Alpha；不要用截图替代源资源。

对每个文件检查：

- PNG 尺寸与节点尺寸一致。
- 透明通道存在且没有意外全透明。
- 文件名稳定、语义化且唯一。
- 相同素材没有重复保存。

把下载清单、目录和预览交给用户。已经透明且内容完整的图层不要再次调用 AI 抠图。

## 停止条件

遇到以下情况时停止变更并报告：

- 找不到精确图片名称或出现无法区分的同名对象。
- 无法进入目标图片的“图层拆分”界面，或进入后缺少门禁要求的可验证界面信号。
- 站点结构变化，无法可靠定位源图显示边界。
- 框选数量与计划不一致且重新校准后仍失败。
- 预览缺块无法通过排序解释。
- 提交、AI 服务或下载会产生未确认的费用。
