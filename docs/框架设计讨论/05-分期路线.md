# 分期实现路线

第 1 期已完成。第 2 / 3 期只定主题；期内功能排队，**未 grilling 不得开做**。第 4 期及以后不排。

命名已落地（D28）：品牌 GMajor；目录 `gmajor/`；全局 `gm`；`gd === gm.data`、`gl === gm.local`（第一刀已落地）；类 `GM*`；接口 `IGM*`。

## 原则

- 先核心，再能力，再业务域
- 每一期结束应有可演示的「绑定轨迹」或可跑通的垂直切片
- 能延后的 SDK / 引导 / 热更等不阻塞核心验证
- **期内逐项加**：每期只定主题，功能一个一个加；**每一项先 grilling 达成共识再落地**，不一次做整期

## 第 1 期：核心底层（已完成）

含原草案第 2 / 3 期提前落地的最小版。不再列入剩余工作。

- 可绑定基类 + 绑定器 + 生命周期 + 失败回滚
- Bundle 一对一桥接、标准入口、绑定可观测
- 全局 `gm`；日志用 `console.*`（不挂 `gm.log`）
- 事件最小版：`GMEventManager` + 基类 `on/off/emit`
- 资源最小版：Bundle + 资源 load（回调式 + 可选进度）
- 视图最小版：`gm.ui` 真场景 / layer / loading、`onEnter`/`onLeave`、`Pf/Ly/Sc` 基类
- Demo：`DemoHome` + `DemoChild`；占用中 unbind 拒绝 → `closeLayer`
- UI 不实现 `IGMLifecycle`（节点生命周期 + `gm.ui`，避免双生命周期）

## 第 2 期：骨架（期内逐项）

- 数据第一刀（已落地）：`gd` / `gl`、LocalStore、假服 RemoteAdapter、bind 建树 / unbind 拆树；无 watch
- 三级开机（已落地）：`User` / `Setting` 为基础包；两份 config；树名=绑定名
- 数据 watch（已落地）：字段 `watch` / `unwatch`；基类自动摘；`spawn` 随包拆；不做深监听 / deps 图
- ~~任务~~：原排队项已拿掉。白板「任务」和 CashGo `dynRenew` 对上后，实为**下载任务调度**，见下方未排；不是通用异步流水线。

## 第 3 期：界面 + 适配（主题已定，项未 grilling）

先最小集，仍须逐项 grilling：

1. loading 验收（已落地）：1.5s 显形、快关不闪；超时仍 20s（Demo 不等满）
2. `gu.addClick`（已落地 D50）：代码注册 click；loading 期间不进回调；`lockTime` 有值才锁。原「全局点击开关」不做，挡操作靠 loading
3. 适配（已落地 D49）：窗多大逻辑分辨率就多大，不做手机 1080p；核心启动同步
4. Alert（系统确认框组件，不是先造独立层槽）
5. 跨包打开别人的预制体

同主题后补（未开、须单独 grilling）：气泡、页签、弹窗基类、按钮、滑动条、定高 / 不定高滚动。

## 第 4 期及以后
