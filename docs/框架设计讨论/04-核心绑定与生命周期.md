# 核心底层框架（绑定 / 生命周期 / Bundle 驱动）

本节描述**全项目必带**的核心底层。绑定/解绑与生命周期是其中一块，不是全部。**尚未定稿。**

## 硬约束复述

1. 核心底层全项目必带；功能由其驱动
2. 核心之外的能力，尽量以 **Bundle + 绑定/解绑** 进入与退出
3. 绑定/解绑本身属于核心（模块及其他功能都可能用）
4. 可绑定对象具备生命周期；**通用契约为共享接口**，逻辑/UI 双基类实现（D02/D03）
5. 与 Cocos Creator 3.8+ 资源分包（Asset Bundle）结合

## 建议的核心概念（草案名，可改）

| 概念 | 含义 |
|------|------|
| 可绑定接口 | 统一生命周期契约；绑定器只认此接口 |
| 逻辑可绑定基类 | 非 UI：实现接口，不强制挂 `Component` |
| UI 可绑定组件基类 | 扩展 `Component` 并实现同一接口 |
| 绑定器 / 绑定上下文 | 执行绑定/解绑，持有关系与上下文 |
| Bundle 桥接 | 将 Bundle 加载/释放 与 绑定/解绑 对齐 |
| 核心驱动入口 | 启动、调度外围能力进入（D04 已锁驱动核心） |
| 全局事件 | 核心常驻 |
| 底层资源加载 | 核心常驻（供 Bundle 桥接等使用） |
| 日志 | 核心常驻 |

### 核心常驻清单（D04，可扩张）

| 类别 | 内容 |
|------|------|
| 驱动与绑定 | 启动入口、可绑定接口、逻辑/UI 双基类及公共部分、绑定器、Bundle 桥接 |
| 基础设施 | 全局事件、底层资源加载、日志 |
| 明确不进首批核心 | 网络、音频、完整 UI 栈、业务系统等 → Bundle 绑定进入 |

## 生命周期：分两边（D05 已确认）

### A. 调用者（编排侧，D06 已确认）

完整进场 / 退场步骤由核心提供，但 **下载等不由底层自动触发**，由上层逻辑按需调用。

**进场：** 解析目标 →（逻辑触发时）下载/拉取 → 成功后处理 → 创建被调用者（若需） → 绑定 → 等到就绪 →（可选）启用  

**退场：**（可选）停用 → 解绑 → 销毁 →（策略决定是否释放 Bundle/缓存）

### B. 被调用者（回调侧）

在调用者流程的各步上接收回调。

**5 阶段（主语义）：**

1. `创建`
2. `绑定`
3. `就绪`
4. `解绑`
5. `销毁`

**7 阶段（兼容扩展，接口预留）：** 在上面增加 `启用` / `停用`（暂停逻辑不卸载）。

与 Cocos 组件关系（D02）：**双轨**——UI 扩展 `Component`；逻辑不强制挂组件。契约形态（D03）：共享接口 + 双基类。

## Bundle 结合策略（D07 已确认：一对一）

- **功能目录 = Bundle = 一个可绑定单元**
- 调用者按名字/路径解析，不维护映射表
- 纯逻辑功能也使用独立 Bundle（可空资源）
- 解绑后是否释放该 Bundle：由上层策略决定（见调用者退场步骤）
- 一功能多包：后期扩张，非首版

## 绑定不只服务「模块」

可能的可绑定形态：

- 能力模块（音频、网络…）
- 业务系统（邮件、商城…）
- 关卡实例
- 交互流水线片段 / 押注阶段钩子
- 临时功能（活动皮肤、小游戏）

因此核心应提供 **通用可绑定基类**，模块只是特化。

## 可观测性（服务「方便跟踪问题」）

建议核心默认提供：

- 绑定栈 / 当前已绑定列表
- 绑定/解绑耗时与失败原因
- 与日志模块对接的标准事件名
