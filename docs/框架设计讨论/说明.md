## 已确认的硬约束

1. 目标引擎：**Cocos Creator 3.8+**
2. **除核心底层框架外**，其他模块尽量用 **绑定 / 解绑** 加载与卸载
3. 绑定/解绑能力本身属于 **核心底层**（不仅服务「模块」，也可能服务其他功能）
4. 可绑定对象都有 **生命周期**，由 **基类** 提供约定
5. 模块与 **Cocos Asset Bundle** 结合使用
6. 整体框架需 **分多期** 落地

## 已确认决策摘要

| ID | 裁定 |

| D18 | **目录**：`gmajor/` 核心 + `main/` 入口 + `bundles/<功能>/` 功能自包含 |

| D22 | **命名**：功能/Bundle 大驼峰，禁止 `-`（见 `.cursor/rules/naming-bundles.mdc`） |
| D23 | **bundles 分层**：允许分组目录；仅叶子=Bundle；绑定名=叶子名 |
| D24 | **大小写**：脚手架小写（gmajor/main/bundles）；功能/分组大驼峰 |
| D02 | **双轨**：UI 扩展 Cocos `Component`；数据/控制等内部逻辑不强制挂组件 |
| D03 | **共享接口 + 双基类**：通用契约用接口；逻辑/UI 基类各自实现；绑定器只认接口 |
| D04 | **驱动核心**：启动入口、可绑定接口与双基类（含公共部分）、绑定器、Bundle 桥接；并常驻全局事件、底层资源加载、日志。名单以后可扩张；网络/音频/完整 UI/业务等仍走 Bundle 绑定 |
| D05 | **生命周期分两边**：调用者负责存在性/下载/成功后处理与绑定解绑编排；被调用者在编排各步上回调。被调用者首版按 5 阶段，为兼容可做成 7 阶段 |
| D06 | **完整进场编排**：解析 →（按需）下载/拉取 → 成功后处理 → 创建 → 绑定 → 就绪 →（可选）启用；退场对称。**下载等由上层逻辑触发，核心底层不自动触发** |
| D07 | **功能 ↔ Bundle 一对一**：目录即 Bundle 即可绑定单元；无映射表。纯逻辑也走独立（可空资源）Bundle。多包依赖留后期扩张 |
| D08 | **入口脚本驱动**：核心提供启动器与绑定编排 API；「何时绑哪个」由项目入口逻辑决定，核心不内置业务清单 |

## 本窗口讨论范围

- **主聊：核心底层框架**（全项目必带；其他能力由其驱动，再以 Bundle 方式绑定进来）
- 绑定/解绑与生命周期是核心的一部分，不是讨论的全部
- **不展开**：各能力模块、业务系统、UI 的实现细节
- 其他工程作参考：**稍后综合**

## 讨论原则

- 一次只锁定一个决策点，依赖关系自上而下拆解
- 事实查仓库；决策归产品/架构方
- 未共同确认「理解一致」前，不写业务实现代码
- 本讨论区文件夹与文档 **一律使用中文命名与中文正文**
