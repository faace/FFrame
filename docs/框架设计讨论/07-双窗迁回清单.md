# 双窗迁回清单

对照拷贝工程 `FFrame-spike-dualwin`（依据 `docs/架构/双窗可行性.md`）相对本仓的**新增能力**。  
本文件是讨论底稿，不是日常手册。讨论完的项再写进 `docs/架构/` / 代码 / Rule。

来源：spike 已证三步可行（异形矿窗、第二窗、指令回矿）。迁回原则已锁：

- 不原样搬 spike；临时焊上的和该进架构的拆开再定。
- 要同时能 **Electron 壳调试** 和 **纯 web / Creator 预览**。
- 验证用玩法包先不迁。
- **清单即工作队列**：短条（含规则候选）都只写在本文；到时**一项讨论、一项执行**。未讨论不改代码、不改 `.cursor/rules`。

状态列：`待讨论` / `已裁定` / `不迁`。尚未逐项 grilling，全部 `待讨论`。

成型度：

| 标记 | 意思 |
|------|------|
| 成型 | 接口/职责清楚，迁回时主要是落点与命名 |
| 临时 | 能跑，但焊在错误层、或标明以后要换 |
| 验收专用 | 只为三步验收，不是产品能力 |
| 坑约定 | 踩过的约束，可能进 Rule，本身不是新 API |

无壳 web：该项在没有 `electron/`、没有第二扇 OS 窗时怎么活。

## 交接（2026-08-23 停窗）

**已落地（不要重做）：** `gmajor/` + `game/` 隔离；`gm.boot` 读 `gp.params.role`；`assets/gmajor/platform/` 认环境；通道 `call`/`send` + `msgid` pending；入站 JSON→对象；主动推 `Gp*` 进 `gm.events`（已无 `gp.on` 表）；`recv` 仅子类。预览验证过 `gp.id === 'web'`。Rule：`01-naming` 平台条 + 事件大类前缀。

**下一窗第一刀（建议）：** Electron 子类接 ipc（`wireCall`/`wireSend` → 壳；回包 `this.recv`）。本仓尚无 `electron/`，对照 `FFrame-spike-dualwin/electron/`。不要把 `window.desktop` 漏给游戏包。

**仍后置：** X01 无壳第二窗；E02 开窗方法（`openUi`/`resizeTo`）；K01 `gm.bridge`（双窗业务，底下再调 `gp`）；具名 `gp.getClip` 等；Q12 按平台拆 `boot`/`entry` 表。

代码入口：`assets/gmajor/platform/GMPlatform.ts`。讨论记录 Q15–Q28 见文末。
