# 设计目标

整理自白板截图，作为框架评估的北极星。

## 目标清单

1. **方便开发**：减少重复与易错点，逻辑容易看懂
2. **方便跟踪问题**：出问题时可快速定位、复现、归因

## 对架构的含义（讨论用，非定论）

| 目标 | 可能导向的设计取舍 |
|------|-------------------|
| 减少重复 / 易错 | 统一生命周期、统一资源与事件入口、少「魔法全局」 |
| 逻辑易懂 | 分层清晰；业务侧尽量薄；约定优于配置爆炸 |
| 方便跟踪问题 | 可观测：日志、模块启停轨迹、Bundle 加载状态、绑定栈 |

## 待讨论

- 「方便跟踪问题」优先靠日志链路，还是靠模块边界 + 生命周期钩子可观测性？
- 是否接受为可观测性付出一点样板代码成本？
