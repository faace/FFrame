## 分三步（不要一次做完）

每步过了再做下一步。失败要分开记：异形失败 / 第二窗失败 / 数据沟通失败。

### 第一步：异形矿窗（单窗即可）

开机就是不打扰：只露一小块地面，窗比较小，出现在屏幕右下。

矿上三个按钮，都走 `gu.addClick`：

| 按钮 | 作用 |
|------|------|
| 展开/收起 | 「只露地面」↔「地面 + 假地下格子」 |
| 加一格 | 外形变大 |
| 设置 | 第二步才真正开 UI 窗；第一步可先摆着或先空接 |

按住矿体**非按钮区**拖，整扇操作系统窗口跟着走。

**通过标准：**

1. 无边框；非格子像素能看到桌面（真透明）。
2. 窗的宽高 = 当前格子并集的包围盒；加一格后 OS 窗跟着变大。
3. 展开/收起、加一格、拖窗都能用。
4. 格子能看懂（例如默认 1 块地面；展开再露 2 块地下；加一格再 +1）。

**本步不必做：** 第二窗、IPC、点穿（点透明处点到桌面）、DPI、真挖矿。

### 第二步：第二窗

「设置」打开一扇**标准 UI 窗**（有边框即可）。矿窗还在，工人/测试用的模拟不能停。

打开后矿窗立刻：

```ts
gm.ui.loadingShow('ui-open', { delay: Infinity, timeout: Infinity });
```

- 挡点击、不露「loading」字、不自动关。
- 矿上要有一个一直跳的数字（或色块闪烁），开 UI 后**仍在变**；点矿没反应、不能拖。
- 关掉 UI 窗后 `loadingHide('ui-open')`，点/拖恢复。

UI 窗里这一步只要能打开、能看见、能关掉。声音开关放到第三步再接真。

**通过标准：** 两窗同时可见；关一扇另扇还在；矿窗数字还在跳；点矿无反应。

### 第三步：数据沟通

UI 窗只做一个**声音开关**，用来验交互。

- **矿窗是唯一权威**，数据在矿窗保存（建议 `gl.MineWin.soundOn`，赋值即落盘）。
- UI 窗**不改数据、不落盘**。点开关只发指令；矿窗处理完再把快照发回，UI 只按快照刷新外观。
- 两窗同样走内核开机，但 UI 角色必须识别自己：不落盘、不写 `gl`，只吃快照、只发指令。

消息**怎么传**（主进程中转、MessagePort、还是别的）在拷贝工程里定。这里只锁协议形态：**指令 + 快照**，不是双写。

**通过标准：** UI 拨开关，矿窗立刻用上（Label / 显隐均可）；刷新后开关外观跟矿窗一致；查落盘只有矿窗在写。

## 已否决（测试时不要走）

- Creator 原生 Windows 包里从 TS 再开第二扇游戏窗。
- 两套独立 Creator 工程、两份 `gd`/`gl` 再双向 merge。
- 单窗大透明画布：角落矿 + 屏幕中央弹窗拼成一张大透明矩形。
- UI 用纯 HTML / 原生对话框。
- 打开 UI 就隐藏矿窗。
- 为禁点另做全局 click 开关（挡操作靠 loading，见 D50）。
- UI 窗自己改 `gl` / LocalStore。

## 失败怎么判

- 真透明做不到 / 窗不能随并集变大 → 异形此路不通，回来改方案。
- 两扇都 load Creator Web 后必崩 / 只能活一扇 → 双 Cocos 此路不通。
- 能开两扇但指令回不到矿窗，或 UI 自己落盘了 → 数据权失败，记原因。
- 必须上两套独立工程才能双窗 → 与需求冲突，判失败。
