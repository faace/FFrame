# 双 Cocos 窗可行性测试（给另一会话用）

目的：先验证「两扇都是 Cocos、同时存在、改设置能回到矿窗」能不能做。未通过前，不要继续收获 / 主线等玩法 grilling。

工程：`d:\creator\FFrame`，Cocos Creator **3.8.8**。游戏将发 Steam，矿是桌面异形窗。

## 产品需求（必须同时满足）

1. **两扇操作系统窗口同时可见、互不打断。**  
   - 矿窗：无边框、可透明异形、可拖。里面是地面 + 地下矿（格子拼出来的外形）。  
   - UI 窗：普通标准窗（有边框也行）。设置 / 主线 / 背包等全部在这里，**屏幕居中**。  
   - 打开 UI 时矿窗还在；工人模拟不能停。
2. **两扇都跑 Cocos Creator**（同一套工程、同一套素材 / 风格）。不是一扇 Cocos、一扇纯 HTML。
3. **UI 窗里可以叠多层**（设置上再叠确认框）。系统窗只保持两扇，不要每块弹窗再开一扇。
4. **数据：矿窗是唯一权威。** UI 只显示、只发指令。在 UI 里改一项设置，矿窗必须马上用上（例如改了「不打扰」或音量，矿窗立刻反映）。不要两份存档对打。

## 已否决（测试时不要走）

- Creator 原生 Windows 包里从 TS `createWindow` 再开第二扇游戏窗（3.8 的 Window 是 RenderWindow，不是第二 HWND）。
- 两套独立 Creator 工程、两份 `gd`/`gl` 再双向 merge。
- 单窗大透明画布：角落矿 + 屏幕中央弹窗拼成一张大透明矩形。
- UI 用纯 HTML/原生对话框（风格不统一，产品不要）。
- 打开弹窗就隐藏矿窗。

## 建议技术路径（测试按这条证伪）

Creator **打 Web 包** + **Electron 壳**（不要用 Creator 的 Windows 原生工程当双窗载体）。

```text
Electron 主进程
 ├─ BrowserWindow 矿：frameless + transparent，load 同一份 Web
 │     启动矿场景；跑模拟；持有数据（可先用一个全局对象代替 gd/gl）
 └─ BrowserWindow UI：普通窗，load 同一份 Web（或同一服务器不同入口）
       启动 UI 场景；只发 IPC 指令，只收快照显示
```

- 一份构建产物，两扇窗 load 同一资源，进不同场景（或带 `?role=mine|ui`）。
- 每个 BrowserWindow 是独立 renderer（两套 JS 堆）。所以 **必须 IPC**，但协议是「指令 + 快照」，不是双写。
- 透明：Creator 勾 `ENABLE_TRANSPARENT_CANVAS`；相机清屏 alpha=0；Electron `transparent: true` `frame: false`。点穿用 `setIgnoreMouseEvents`（可后测）。

## 最小证明（这个会话只做这些）

做一个最小 Electron 壳 + 现有工程的 Web 构建（或更小的双场景空包），证明：

| # | 用例 | 通过标准 |
|---|------|----------|
| A | 同时开两扇 Cocos 窗 | 两窗都能动、都能看见，关掉一扇另扇还在 |
| B | 矿窗透明 / 无边框 | 能看到桌面从「非矿像素」透出来（异形可先用一张挖了洞的图） |
| C | UI 窗标准、可居中、可叠两层 | 例如点按钮再弹出第二块面板，矿窗仍在 |
| D | 指令回矿 | UI 点「改一个数」，矿窗画面立刻变（Label / 颜色 / 显隐均可） |
| E | 同一套资源 | 两窗显示同一张图集或同一个预制体风格，不是两套工程 |

**不必做：** 挖矿玩法、格子扩张、Steam、离线、点穿、DPI、窗随矿长大、不打扰模式。

## 失败则怎么判

- 两扇都 load Creator Web 后必崩 / 只能活一扇 → 双 Cocos 此路不通，回来改方案。  
- 能开两扇但 IPC 改数矿窗收不到 → 记原因（preload、contextIsolation、时机）。  
- 透明在 Electron 里无效 → 记是宏、CSS、还是 Electron 版本问题；双窗本身仍可算过。  
- 必须上两套独立工程才能双窗 → 与需求冲突，判失败。
