# 用户规则(复制到 Cursor 设置 → Rules → User Rules)

下面三段各是一条用户规则:在 User 那一栏点 **+ New**,把每个代码块里的文字整段粘贴进去,三段分开建三条。
这是应用设置,不是文件,只能手动粘贴;换电脑时重新粘贴一次(也可能随账号同步,先看一眼 User 栏里有没有)。

## 1. 工作流

````text
工作流:遇到非小任务(新功能、需求不明确、涉及多个模块)时,先使用 grilling skill:提议 小/中/大 路径并等我确认;grilling 达成共识后只写 docs/specs/<功能>/共识.md 然后停下,我明确说"开干/实现"之前不得改代码。小任务(改 bug、微调、单文件)直接做。大功能用 /spec 拆 ticket、/implement NN 逐条实现(每条新开 session)、/review 审查;中等任务共识后直接 /implement。
````

## 2. 临时产物

````text
临时产物:一次性的测试脚本、试跑输出、验收截图、对照图，只写仓库根 del/。不要写到 apps/、docs/、src/、assets/ 或其它会进 git status 的路径，看完就留在 del/，不要为了接着看而留在源码旁边。del/ 不存在就建，并确保 .gitignore 里有 /del/，建了要告诉我。仓库里随提交进库的正式测试不走这条。项目规则另有约定的，以项目规则为准。

用户没另外指定位置时，这一次要写的东西放进 del/ 下一个新建文件夹，不要直接丢在 del/ 根上。同一个对话窗口、同一件事共用这一个文件夹，窗口里换成另一件事再另建，用户点名已有目录就用那个。文件夹名用短的中文写清这次做什么，例如 del/排查登录超时/，不要用 probe、sheet3、v7、tmp 这类看不出用途的名字。文件少就平放，脚本、日志、图一多再分 脚本/、输出/，不要为了分类先造空目录。已经堆在 del/ 根上的旧文件，没让整理就不要搬。
````

## 3. 临时总结

````text
临时总结:用户输入 #临时总结（可附带短标题）时，先把记录写成文件，再回复路径。不要再 grilling、不要问「更哪几条」、不要问结果该标哪一档。项目规则另有约定的，以项目规则为准。

完成标准是磁盘上有 docs/临时总结/日期-结果-短标题/README.md，并且 docs/临时总结/索引.md 有对应一行。五段正文写进这个文件。对话里只回复路径、结果档和标题，不要把总结正文贴在对话里当作交差。没写成文件就还没做完。

新建时记这个窗口做到哪。改已有夹时，先读原来的 README.md：需求和尝试保留，本窗口新做的、原文里没有的再补上。不代替 docs/specs/ 的共识文档。不转抄整段聊天。不写密钥、.env、cookie。写完不 commit、不 push。

找到哪一夹，按这个顺序，命中就用，不另开：
1. 这次消息里有 docs/临时总结/ 下某份 README.md 的路径，或 @ 了那个记录夹：改这一夹。
2. 本对话已经写过一夹：改那一夹。后面又带了新短标题也不换标题、不新开。
3. 否则新建。短标题用指令后面的字。没带就从窗口内容起一个短中文名，回复里写出来。文件夹名不要用 \ / : * ? " < > |。

新建时日期用当天下的 YYYY-MM-DD。重写时日期和标题不动。结果只有 有结论、未定、否掉。拿不准就标未定。状态变了只改文件夹名中间那一段，例如 2026-10-30-未定-登录超时排查 改成 2026-10-30-有结论-登录超时排查。

README.md 五段顺序固定，不在末尾另叠一节：
1. 需求与情况：要解决什么，当时是什么情况。已有夹里写过的保留；本窗口把需求说清楚了、原文没有的，补进去。
2. 尝试：做过的尝试。成功、没成、中途停下的都写。每条写试了什么、当时看见什么。已有夹里的条目保留，本窗口新做的、原文里没有的补在后面。同一条不要写两遍。
3. 结论：按合并后的全文重写，一两句。有结论就写定了什么；未定就写还卡在哪；否掉就写哪条不要再试。
4. 接着做：按合并后的全文重写。只列还没完的点，每条写下一步。已经否掉的不放这里。未定时至少一条。有结论或否掉、且没有待办时，写「没有待办。」
5. 产物：按合并后的全文重写。原来写过的 del/ 目录这次仍要数，本窗口新用到的目录加进去。

产物只计这次这件事用到的那个 del/ 目录，不扫整个 del/。用到多个子目录就分开写。打开目录数清楚，不要凭记忆估。各写两行：子文件夹多少个（不含目录自己）；每种扩展名多少个文件，没有扩展名的单独计。不把每个临时文件的名字列进 README。记录夹里拷进来的文件同样两行，和 del 分开。这次没有用到 del/ 就写「这次没有用到 del 目录。」

从 del 拷什么，不整夹搬：结论要靠的结果图、对照图拷进记录夹；一次性脚本、日志、中间图留在 del/，README 的尝试里写清路径和它说明了什么；这次消息 @ 了具体文件算点名，拷过去；@ 的是整个文件夹，仍只拷结果图、对照图和点名文件。文件少就平放在 README.md 旁边，图或脚本多了再放 图/、脚本/，不要先造空目录。挑出来大约超过 10 个文件，或合计超过 20MB：README 先落盘，这些先不拷，回复里列清单，等用户点头再拷，产物里写明尚未拷入。

索引：docs/临时总结/索引.md 没有就先建表头。新的一行加在表的最上面。同一夹重写时改原来那一行，不另加。改名后链接和结果档一起改，日期和标题不动。一行四列：日期、结果、标题、指向该夹 README.md 的链接。不抄正文。

回复：文件写完再回复。回复里必须有文件夹路径、结果档和标题。有文件等点头再拷时，把清单附上。不要用一段聊天总结代替上面的文件。
````
