# 轻提示 共识

## 目标

做通用一句话提示控件 `PfGMToast`：弹一句、自动消失、不进弹层栈、不挡操作。补上动物园策划点名的三处「太重了不能借确认框」的场景（棋盘已满、获得园景素材、提示不适用）。

## 已定决策

1. **路径**：中。grilling → 本文件 → 确认后 `/implement` → `/review`。

2. **名字**：`PfGMToast`。脚本 `gmajor/ui/PfGMToast.ts`，预制体 `gmajor/prefabs/PfGMToast.prefab`。
   - 图集槽名已经是 `toast`，类名跟着它；框架自带预制体固定 `Pf` + `GM` + 名。

3. **形态：静止，不飘升。**
   - 固定在停靠点，只做透明度淡入淡出。文字不上浮、不缩放、不位移（重排时的让位位移除外）。
   - 理由：① 白图期是白底横条，飘升会变成白方块上升，文字居中、停留时长、连调三次这些验收项全看不清；② 动物园那三处都是失败原因或条件说明，不是奖励反馈，静止更对味；③ 叠加规则只剩垂直堆叠一种；④ 代码少约三成，也没有「正在飘时又来一条」的打断问题。
   - 奖励飘字（`+1` 金币那种）将来另做 `PfGMFloatText`，不混进 Toast。

4. **尺寸 480×72**，不是槽预留的 480×128。
   - 理由：一句话单行，128 高在 1280 屏上像一张卡片。
   - 内宽 408 = 480 − 九宫格左右各 20 − 左右留白各 16。
   - **副作用要交给画图的人**：源图九宫格边 40（显示 20），上下各吃 20 后中间只剩 32 的可压横带，所以真图**中间那条横带必须画平**（纯色或细纹理），装饰只能落在四边九宫格区内，否则压到 72 会糊。

5. **位置：三档预设，一个项目只能用一种。**
   - `PfGMToast.setAnchor('top' | 'center' | 'bottom')`，默认 `top`。
   - 位置记在**模块级变量**，不在实例上，也不对外暴露在 `show()` 里 —— `show(text)` 永远不收坐标。
   - 第二次传**不同的值**：`console.warn('[PfGMToast] 位置已定为', anchor, '，忽略', one)` 并保持第一次的值；传相同值静默通过（开机重复调不刷日志）。
   - y 值取挂载容器实际高度现算，不写死：`top` = `H/2 − 120 − 36 − i×84`（往下堆）；`center` = `0 − i×84`（往下堆）；`bottom` = `−H/2 + 120 + 36 + i×84`（**往上堆**，否则第三条跑出屏底）。
   - 理由：`top` 不压主操作区，和弹窗标题同侧；放中间会被误读成 loading；放下方会被底部导航挤。三档够覆盖「偏上 / 中间 / 偏下」，又不至于让每个调用方各摆一个坐标。

6. **停留时长：基础 2.0 秒；超过 12 字每字 +0.05 秒；上限 3.5 秒。**
   - 动物园最长那句「完成合成任务获得园景素材」12 字刚好吃满 2 秒不缩；「提示不适用」5 字也不至于短到看不清。

7. **淡入淡出：入 0.15 秒、出 0.2 秒，只动 `UIOpacity`。**
   - 不动根节点缩放（`0→1.1→1` 是给面板的动效，Toast 不该抢视线），不重复淡入已经在屏幕上的条。

8. **多条并存：垂直堆叠，最多 3 条。**
   - 新的插**最上面**（槽 0），已有的整体往下挪一格，0.15 秒缓动让位，不是瞬移。
   - 第 4 条进来时把槽 2 那条**立刻淡出并销毁**（不等它自然到点），其余上移，新的进槽 0。
   - 上限 3 的算式：3×72 + 2×12 = 240；`top` 档从 y=484 排到 244，全在屏幕中线上方。槽高和间距是常量 `height: 72` / `gap: 12`，不对外暴露。
   - 理由：那三处都是「刚发生的失败原因」，排队会把已经过期的提示晚两秒才显示；超过 3 条本身说明有代码在刷提示，挤掉最老的比继续排更不误导。

9. **每条自己的计时，重排不动别人的剩余时间。**
   - A 条 2.0 秒、B 条 3.0 秒同时显示：A 先消失，B 往上一格继续到 3.0 秒。
   - A 消失时只是 B 的位置变，B 的定时器**不重置、不取消**。这条明写进验收，是最容易写错的地方。

10. **相同文字去重。**
    - 同一句还在屏幕上时不新增节点，只把那条的计时重置、移到槽 0、重新淡入一次。
    - 理由：动物园里「提示不适用」「棋盘已满」是连点生成器会反复触发的，不去重时连点五下就把别的提示全顶没了。

11. **不可点、不挡输入，写死进共识。**
    - 根节点与其他子节点**禁止**挂 `BlockInputEvents` / `Button` / 任何 `TOUCH_*` 监听。
    - 不注册 `gu.addClick`，点了没反应。
    - 容器 `toasts` 满屏但透明、不吃事件，点击直接穿透到后面的按钮。
    - 这是它和 `gm.alert`、`loadingShow` 的区别本身，不写死的话下一个改的人会顺手加个「点一下提前关」然后把它变成挡输入的东西。

12. **文字：单行不换行，`Label.Overflow.SHRINK`，28 号，深墨 `92,64,32`，不描边。**
    - 和 `PfGMBtn.place()` 同一套写法（`overflow = SHRINK` + `enableWrapText = false`）；换行会让 72 高放不下两行 28 号。
    - 不描边依据规则「奶油底上的深色字不描边」（标题、步进数字、页签字、说明字）；白字描边 3 只给彩色按钮和进度条。将来真皮若改成深色底，要回来改这一条。

13. **对外三个方法，全部静态。**
    - `PfGMToast.show(text: string): void` —— 弹一句，空串 warn 后忽略。
    - `PfGMToast.hide(): void` —— 全部立刻收起（切场景、回主菜单时用）。
    - `PfGMToast.setAnchor(one: GMToastAnchor): void` —— 见第 5 条。
    - 脚本本身仍是 `extends GMComponent` + `@executeInEditMode(true)` 的实例控件（和 `PfGMCheck.ts` 一个写法），静态方法只是对外入口。
    - **不做 `gu.toast()`**：那会让 `GMUIManager` 反向 import `PfGMToast`，而 `PfGMToast` 要 `gu`，形成 `GMUIManager → PfGMToast → GMLauncher → GMUIManager` 的循环。
    - **不预载、不进 `config.boot`**：首次 `show()` 时从已加载的 `GMUI` 包 `load('PfGMToast', Prefab)`，之后复用同一个 Prefab，模块级变量记住；同时 `loading` 标志防并发重复 load。

14. **预制体结构：根 + `bg` + `label`，与 `PfGMCheck`（`box`/`mark`）、`PfGMItemCell`（`bg`/`label`）一路。**

    ```text
    PfGMToast          根：PfGMToast 脚本 + UITransform 480×72
    ├── bg             Sprite，applySkin('toast')，SLICED
    └── label          Label，预制体里就挂 db://gmajor/fonts/main.ttf
    ```

    - `label` 在预制体里就挂好字体，不在运行时 `new Node()` 造（`PfGMBar` 那样造是因为它要在任意节点上活；这里是自己的预制体）。
    - 预制体里不嵌任何嵌套预制体实例，`nestedPrefabInstanceRoots` 保持 `null` —— 也就没有「漏登记退化成空节点」那个坑。
    - 预制体节点 `_layer` 写 33554432（编辑器 UI 默认层）；运行时由 `createTs` 递归刷成 Overlay 层，不手设。

15. **挂载：由 `GMUIManager` 给一个专用容器 `toasts`，和 `layers` / `loading` / `alerts` 平级。**
    - `GMUIManager.ensureOverlay()` 里加一行，与另外三个一模一样：
      ```ts
      this.toastsRoot = this.makeFullNode('toasts', root); // 轻提示：画在确认框之上，不吃事件
      ```
    - 字段 `private toastsRoot: Node | null = null; // 轻提示；满屏但不挡输入`
    - 新增 getter：
      ```ts
      /** 轻提示容器。PfGMToast 挂这下面；满屏、透明、不挡输入 */
      toastRoot(): Node | null { this.ensureOverlay(); return this.toastsRoot; }
      ```
    - `makeFullNode` 已经给了 `UITransform` + `Widget` 四边 0 + `ALWAYS`，窗口变了自己重铺，**`syncOverlayToView()` 不用改**。
    - **不挂 `BlockInputEvents`**，也不加进 `syncOverlayToView` 的遍历。
    - 为什么不塞进现有三个：① `layersRoot` 会被 `closeAll()` 和切场景整批拆掉，Toast 不该跟着弹窗一起清；② `alertsRoot` 在 `addClick` 里享受「loading 期间也能点」的特权（`isUnder(target, alertsRoot)`），Toast 挂进去是白蹭特权、语义错；③ 需要一个能算屏高的父节点做堆叠基准。
    - z 序：追加在 `alerts` 之后，画在确认框之上。`top` 档离顶 120、弹窗面板从 240 起，不重叠；`center` / `bottom` 档可能压在弹窗上，但容器不吃事件，看起来盖住、点下去穿过去。

16. **定时器用 `GMOverlayHost` 的具名调度，不用别的花样。**
    - 每条一个名字（`toast:<seq>`），`scheduleNamed(name, 秒, () => drop())`，销毁前 `unscheduleNamed(name)`。
    - 容器是 persist 节点，`scheduleOnce` 跟着它走，切场景不中断计时。

17. **`node.layer` 跟父节点。**
    - 一律用 `gu.createTs(prefab, { parent: toastsRoot })`，它内部 `applyLayer(node, parent.layer)` 递归刷层（`GMUIManager.ts:463`）。
    - 这就是上次滑条 `fillClip` 用默认层、Overlay 相机不画的那个坑的现成解法，不自己再写一遍。

18. **皮暂缺，走白图；真图由图集窗口统一画。**
    - 代码照约定 `applySkin('toast', ...)`；缺这一张会打一条 `[Skin] 缺 toast` warn 然后给内置白图，这是约定内的正常态。
    - **不 try/catch 吞掉**、不用别的槽顶替、不在本窗口画图、不碰 `ctrl.json` / 图集 / plist。
    - 交给画图窗口的规格：槽名 `toast`，显示 480×72，九宫格边 20（源图 40，源图按 2 倍出即 960×144），中间横带画平，装饰只落九宫格区内；`ctrl.json` 里该槽现有的 `rect [704,1570,960,256]` / `display [480,128]` 是按 128 高留的，由画图窗口按 72 高重排。代码不读 `display`，用脚本顶部常量，所以两边不用同时改。

19. **切场景不主动清 Toast。**
    - Toast 挂在 persist Overlay 上，最长 3.5 秒自然消失，不值得为它加清理逻辑。
    - 需要立刻清时由调用方调 `PfGMToast.hide()`。

## 验收标准

1. 调一次能弹出一条白底提示，文字居中，按时长自动消失。
2. 连调三次：三条从上往下排成 72 高、12 间距的一列；新的在最上面。第 4 次时最老那条立刻消失、其余上移、新的进槽 0。
3. 两条时长不同（如 2 秒和 3 秒）：短的先消失，长的那条**位置往上补但计时不被重置**，仍按原定时间消失。
4. 同一句话在屏幕上时再调一次：不新增节点，只重置时长并回到槽 0。
5. 提示在的时候，点它后面的按钮能点到（不挡操作）；点提示本身没有任何反应。
6. 提示不进弹层栈：弹 Toast 时打开一个弹窗、再关掉，Toast 不受影响；反过来也一样（Toast 弹出时 `closeAll()` 不会带走它）。
7. 缺图只有一条 `[Skin] 缺 toast` warn，没有红错刷屏。
8. `setAnchor('bottom')` 后堆叠方向变成往上，`center` 落在屏幕中线；第二次传不同的值只 warn、位置不变。
9. 不改动已完成的 9 个控件的表现。
