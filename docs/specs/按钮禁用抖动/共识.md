# 按钮禁用抖动 共识

## 目标

`PfGMBtn` 禁用后仍然能点到。点下去不执行业务回调，按钮水平抖一下，表示现在不能操作。

## 已定决策

1. **路径**：中。grilling → 本文件 → 先做一版看效果。
   - 理由：一块手感，接法已经问完。用户要求先看到抖动再往下定。

2. **禁用被点到时不跑业务回调**。也不做按下的缩小和压暗。只水平抖一下，然后回到抖之前的位置。可点按钮仍是现在的缩小加压暗。
   - 理由：抖是「不能点」的反馈。再缩小、再压暗会和已经去色的禁用外观叠在一起。

3. **凡是 `PfGMBtn.setEnabled(false)` 都这样**。步进到最小值再点减号、到最大值再点加号，也是抖一下，数值不变。按钮和弹窗展示加一颗始终禁用的样例，字是「禁用」。没有禁用状态的节点不动。
   - 理由：禁用只有这一处入口。步进用的就是它。展示页原先看不出禁用。

4. **抖动**：水平 10 像素，左右各两下再回到原位，幅度变小（+10、−10、+6、−6、0），五段合计约 0.28 秒。不播声音。
   - 理由：设计分辨率宽 720。10 像素在小档上能看见，大档也不会晃出一截。

5. **这一版顺手定的边界**（为了能看效果，没有再单问）：
   - 抖还没完又点：先回到原位再重开，避免越抖越偏。
   - loading 开着：跟普通点击一样不进回调，也不抖。确认框上的点击仍可点。
   - `setEnabled(true)`：停抖并回到原位，恢复可点。
   - 禁用仍保持 `Button.interactable` 为开，否则 Cocos 不派发点击，抖不出来。

6. **禁用外观是去色后再往白走三分之一**。底板和图标走 `gmajor/prefabs/btn-disabled.effect`，不再整颗乘 `0.55`。字的底是 `220`，描边先按引擎灰度系数去掉色相，然后和底板一起往白走三分之一。
   - 理由：第一版偏深，而且颜色还在。只要变灰，再浅三分之一。五个主题灰完明暗不一样，跟原图亮度走。

7. **展示页底部用小档排出五个主题的禁用**。主色、次要、信息在上一行；醒目、中性在最下面，这两颗带图标。五颗小档并排放不下（180×5 超过面板宽 640）。原来的三颗尺寸方钮和四颗图标钮并成一行，给这两行让位置。

## 不做什么

- 不给禁用加声音。
- 不在检查器上加禁用开关。展示页在运行时 `setEnabled(false)`。
- 不改可点按钮的按下缩小和压暗。
- 不给没有 `PfGMBtn` 的节点加这套抖动。
- 效果没定之前不升 `gm.version`，不写 `CHANGELOG.md`。
- 不改 `.cursor/rules/`，规则要等单独确认。

## 验收标准

- [ ] 按钮和弹窗展示底部有五颗变灰的小档：主色、次要、信息，以及带图标的醒目、中性。点它们不弹窗，水平抖一下后回到原位。五颗灰的深浅不一样。
- [ ] 连点不会把按钮抖离原位。
- [ ] 旁边可点的按钮仍是按下缩小并压暗，回调照常。
- [ ] 步进到最小值点减号、到最大值点加号：数值不变，按钮抖一下。
- [ ] loading 开着时，禁用钮不抖。

## 涉及范围

- `FFrame/gmajor/ui/PfGMBtn.ts`：禁用仍收点击；`shake` 做水平抖动。
- `FFrame/gmajor/ui/GMUIManager.ts`：`addClick` 在禁用时改走 `shake`，按下反馈跳过。
- `FFrame/gmajor/ui/PfGMStepper.ts`：到头的加减号沿用 `setEnabled`，位置写在禁用刷新之后，避免抖的过程中被摆回去。
- `FFrame/assets/game/bundles/Demo/DemoHome/LyButtons.ts` 和 `LyButtons.prefab`：加一颗始终禁用的「禁用」。
- `FFrame/docs/界面组件/说明.md`、`进度.md`，`docs/架构/核心简介.md`：改掉「禁用后不可点」的说法。
